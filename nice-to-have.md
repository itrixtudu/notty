# Nice-to-Have Roadmap

> **Consolidated on 2026-08-01.** The active roadmap now lives in
> [RELEASE.md](RELEASE.md#post-release-defense-in-depth-roadmap), alongside the
> release requirements it must not weaken.

The specific per-agent Unix-user design is post-release defense in depth. The
underlying outcome is not optional: before `v1.0.0`, one agent must already be
unable to read or use another agent's credentials through an equivalently
reviewed isolation or credential-broker boundary.

The consolidated roadmap also records the clean-room network observation and
stronger audit-evidence integrity follow-ups. The original design material has
been incorporated into `RELEASE.md` so this file carries no separate
requirements.
